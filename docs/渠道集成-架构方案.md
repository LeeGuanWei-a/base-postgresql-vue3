## 1. 系统定位

将**企业微信 / 微信公众号 / 微信小程序 / 支付宝** 四个渠道以**两个独立 Maven 模块**的方式集成进 `base-postgresql-vue3` 项目，作为业务系统（`basic-admin-core`）的**外部能力提供者**。

| 维度 | 内容 |
|---|---|
| **使用方** | 业务中后台（`basic-admin-core`）的 Service / Controller |
| **触发方式** | 同步调用（消息推送、支付下单）+ 异步回调（企微事件、支付宝 notify） |
| **数据形态** | HTTP JSON / XML（企微）、HTTP form（支付宝） |
| **范围边界** | 仅做"渠道适配 + 业务编排"；不做 SDK 重写，不做 UI 中间层 |
| **不做清单** | 不做 Flowable 编排（用户已确认调接口即可）、不做企业微信组织架构替身、不做支付路由策略、不做多租户分账 |

**关键决策**（详见 ADR）：
- 两个模块**不合并**——依赖、升级节奏、运维责任都不同
- **不使用 SDK 的 spring-boot-starter**——WxJava 的 starter 编译时锁 SB 2.5.15，本项目用 SB 4.1.1
- **自实现 token 存储**——多实例部署时避免企微限频

## 2. 约束与质量属性

| 维度 | 目标 | 备注 |
|---|---|---|
| **可靠性** | 单实例故障不影响 token 共享；Redis 不可用时降级到内存（仅限单实例） | 企微 token 限 7000 次/2h/企业 |
| **一致性** | access_token 在 Redis 内强一致（多进程通过锁串行刷新） | 不强求严格 exactly-once |
| **限频** | 企微 1500 次/分钟；支付宝按业务接口文档 | 客户端内置退避重试 |
| **可观测** | 关键路径 INFO 日志；异常 ERROR；调用耗时 WARN（>1s） | 不接 OpenTelemetry 后续按需 |
| **可维护** | 业务编排与 SDK 调用分层；变更 SDK 不影响业务 | |
| **安全** | 所有回调必须验签；Token 不入日志；私钥走环境变量 | |
| **可用性** | 目标 99.5%（依赖企微/支付宝 SLA） | 本系统不承担更高 SLA |

**最强约束**：**企微/支付宝限频**。一旦超过，整企业被风控 1-24 小时。设计上必须把"调用次数"和"调用方"绑死——单实例可接受，多实例必须共享 token + 串行刷新。

## 3. 总体架构

### 3.1 模块位置

```

├── basic-admin-core/                          (业务系统：sys_user / sys_notice / sys_dept)
├── basic-admin-api/                           (启动模块：依赖下面所有 extend-* 模块)
│
├── extend-quartz/        (定时任务，本项目已有)
├── extend-generator/     (代码生成，本项目已有)
│
├── extend-wecom/         [新]  WxJava 4.8.6.B
│   ├── config/           WeComProperties / WeComConfiguration / RedisWxCpConfigStorage
│   ├── client/           (后续) WxCpService 薄封装
│   ├── callback/         (后续) /wecom/callback 入口 + 验签 + 幂等
│   ├── sync/             (后续) 通讯录 → sys_user / sys_dept
│   ├── message/          (后续) 应用消息推送编排
│   ├── approval/         (后续) 审批数据拉取
│   └── customer/         (后续) 客户联系 SCRM
│
└── extend-alipay/        [新]  alipay-sdk-java 4.40.1044.ALL
    ├── config/           AlipayProperties / AlipayConfiguration
    ├── trade/            (后续) 下单 / 退款 / 查询
    ├── notify/           (后续) 异步通知验签
    └── settlement/       (后续) 对账文件解析
```

### 3.2 调用路径

**主动调用（业务 → 渠道）**：

```
SysNoticeService.publish(notice)
    └─→ WecomMessageService.sendToAll(notice)
            └─→ WxCpService.getMessageService().appChatSend(...)
                    └─→ RedisWxCpConfigStorage.getAccessToken()  ← Redis 共享
                            └─→ POST https://qyapi.weixin.qq.com/...
```

**被动接收（渠道 → 业务）**：

```
企微事件 ──POST /wecom/callback──→ WecomCallbackController
    └─→ WxCpCryptUtil.decrypt(msg)                  ← 验签 + 解密
        └─→ 幂等判断（按 msgId 去重）
            └─→ 异步入队（5 秒内必须返回 success）
                └─→ WecomEventConsumer.handle(event)
                    └─→ 业务处理（同步通讯录 / 更新审批状态 / ...）
```

### 3.3 数据模型

| 表 | 来源 | 用途 |
|---|---|---|
| `wecom_config` | extend-wecom | 多企业/多应用配置（corpId/agentId/secret 列表） |
| `wecom_token` | extend-wecom | 可选：token 持久化（当前用 Redis，可降级到表） |
| `wecom_dept_map` | extend-wecom | 企微部门 ID ↔ sys_dept.dept_id 映射 |
| `wecom_user_map` | extend-wecom | 企微 userid ↔ sys_user.user_id 映射 |
| `wecom_msg_log` | extend-wecom | 发送消息记录（msgid / 状态 / 重试次数） |
| `wecom_callback_idem` | extend-wecom | 回调幂等表（msgId 主键） |
| `wecom_approval` | extend-wecom | 审批数据快照（oa/getapprovalinfo 拉取） |
| `wecom_external_contact` | extend-wecom | 外部联系人（客户联系 API） |
| `alipay_config` | extend-alipay | 支付宝应用配置（appId / 公钥/证书路径） |
| `alipay_trade` | extend-alipay | 交易记录（outTradeNo / tradeNo / 状态） |
| `alipay_refund` | extend-alipay | 退款记录 |
| `alipay_notify_log` | extend-alipay | 异步通知原始报文（防纠纷） |

**所有 wecom_* / alipay_* 表 schema 单独出**：见 `渠道集成-数据库设计.md`（后续）。

### 3.4 关键状态机

**Access Token 生命周期**：

```
[未初始化] --调 getAccessToken()--> [请求中-持锁]
                                          │
                                          ▼
                                调企微 /cgi-bin/gettoken
                                          │
                            ┌─────────────┴─────────────┐
                            ▼                           ▼
                       [token 有效]               [token 无效/过期]
                       (Redis 中有)              (Redis 读不到)
                            │                           │
                            ▼                           ▼
                       返回 token                  调 refreshToken()
                                                       │
                                                       ▼
                                                 写回 Redis (TTL = expiresIn - 60s)
                                                       │
                                                       ▼
                                                 返回新 token
```

**支付宝异步通知状态机**：

```
[收到 POST] --验签--> [验签失败:直接 200+fail,不入库]
        │
        └─→ [验签成功] --查重--> [重复通知:直接 200+success]
                │
                └─→ [新通知] --落库 notify_log--> [业务处理]
                        │
                        ├─→ 成功: 200 + success
                        └─→ 失败: 200 + fail   ← 失败也返 200,否则支付宝会重试轰炸
```

## 4. 关键决策 ADR

### ADR-001: 两个模块独立，不合并为 extend-channel

| 项 | 内容 |
|---|---|
| 背景 | 微信生态（WxJava）和支付宝（官方 SDK）业务模型、依赖、升级节奏完全不同 |
| 候选 | ① 合并成 extend-channel ② 独立两个模块 |
| 选择 | ② 独立 |
| 放弃 | ① 合并后 fastjson 1.2.83（支付宝）会污染 WxJava 的 Gson 依赖；alipay-sdk-java 一周几版的升级节奏会拖垮 WxJava 那边 |
| 退出 | 哪天想合并，重命名 + pom 重组即可，业务代码不动 |

### ADR-002: 不使用 WxJava 的 spring-boot-starter

| 项 | 内容 |
|---|---|
| 背景 | WxJava 的 `wx-java-cp-spring-boot-starter` 编译时锁 SB 2.5.15（javax.* / spring-data-redis 2.3.3） |
| 候选 | ① 用 starter ② 手写 Configuration + 自实现 WxCpConfigStorage |
| 选择 | ② |
| 放弃 | ① SB 4 下 starter 自动配置不生效；spring-data-redis 2.3.3 与项目 4.x 冲突 |
| 代价 | 失去 starter 提供的"开箱即用"——我们用 50 行 Configuration 替代 |

### ADR-003: access_token 持久化到 Redis

| 项 | 内容 |
|---|---|
| 背景 | 多实例部署时，每个实例默认都去拉 token，会触发企微"短时间大量刷新"风控 |
| 候选 | ① WxJava 默认内存实现 ② Redis 持久化 |
| 选择 | ② |
| 放弃 | ① 单实例 OK，多实例不行 |
| 退出 | 改回内存只需换 `WxCpDefaultConfigImpl` 子类，零业务影响 |

### ADR-004: 不用 alipay-easysdk，用官方全量 SDK

| 项 | 内容 |
|---|---|
| 背景 | 官方有两个 SDK：易用版（alipay-easysdk，2023-05 停更）和全量版（alipay-sdk-java） |
| 候选 | ① easysdk ② alipay-sdk-java |
| 选择 | ② |
| 放弃 | ① 停更 2 年；只覆盖常用支付接口，营销/会员/小程序接口缺失 |
| 代价 | 依赖较老（fastjson 1.2.83、bcprov-jdk15on 1.62）——已 exclude 老 BC，统一用 jdk18on；fastjson 必须保留（SDK 内部用） |

### ADR-005: 回调 5 秒内必须返回，分异步处理

| 项 | 内容 |
|---|---|
| 背景 | 企微/支付宝对回调响应超时（5s/3s）会重试 3 次，然后告警 |
| 候选 | ① 同步处理到入库再返 ② 收到立即入队 + 异步消费 |
| 选择 | ② |
| 放弃 | ① 业务重时（同步 1000 个员工）必超时 |
| 代价 | 引入消息中间件或内存队列——本项目用 `extend-quartz` 的 `JobInvokeUtil` 思想做轻量 in-process 队列（单实例）；多实例要切 Redis Stream / Kafka |

### ADR-006: 私钥/secret 走环境变量，不入 yml

| 项 | 内容 |
|---|---|
| 背景 | yml 提交 git 后即泄露，即使 dev 配置也是事故 |
| 候选 | ① 明文写 yml ② 全部走 `${ENV_VAR:default}` 占位 |
| 选择 | ② |
| 实施 | `application-dev.yml` 用占位符带默认值（方便首次启动），`application-prod.yml` 不带默认值（强制环境变量） |
| 退出 | 改回明文只需要把占位符替换成实际值——但**永远不要这样做** |

### ADR-007: 演进锁死点

- **WxJava 4.8.x 锁定**——升 5.x 是破坏性变更（包名重组），需要单独升级窗口
- **alipay-sdk-java 4.40.x 锁定**——5.x 移除了一些老 API，需逐个迁移
- **JDK 21 / SB 4 锁定**——其他分支如果回退到 SB 3 / JDK 17，本模块代码**原样可移植**（不依赖 SB 4 / JDK 21 独有 API），但需要重新选 BC 版本

## 5. 里程碑

| 阶段 | 范围 | 验收标准 | 触发升级的量化信号 |
|---|---|---|---|
| **M0 - POC（已完成）** | 装配 SDK + Redis token + 两个健康检查端点 | 启动后 `/wecom/health/1` 返回企微 40001（凭证错）；`/alipay/health/1` 返回私钥空 | — |
| **M1 - 通讯录 + 消息** | 成员/部门/标签同步；应用消息推送；OAuth2 扫码登录 | 公告发布后企微手机收到；员工扫码后能登录 | 每周至少 5 次"通知不到"工单 |
| **M2 - 审批 + 回调** | oa/getapprovalinfo；通讯录/审批事件回调；5 秒内响应 | 企微提交审批 → 后台可见；后台驳回 → 企微收到 | 月调用量 > 1 万 |
| **M3 - 公众号 + 小程序** | 公众号菜单/模板/网页授权；小程序 unionid/订阅消息 | H5 能微信登录；小程序能 unionid 打通企微 | B 端用户开始用公众号 |
| **M4 - 客户联系 SCRM** | 外部联系人/客户群/欢迎语/朋友圈/客户标签 | 加好友后自动打标签；群发按标签 | 客户运营业务立项 |
| **M5 - 支付宝支付** | 下单/退款/查询/异步通知 | 沙箱走通；生产可下单 | 业务需要收款 |
| **M6 - 考勤/会议/微盘** | 按需追加 | 按业务需求 | 出现"考勤同步"工单 |

**本次明确不做**（直到有信号）：
- 支付宝商家券、营销活动（业务未启动）
- 微信支付分、广告平台（不在中后台范围）
- 企微硬件设备、人脸核验（需独立硬件投入）
- 跨企业互联（除非企业真的要做上下游协同）
- Flowable 工作流编排（用户已确认调接口即可）

## 6. 审查与遗留风险

### 6.1 已覆盖项

- [x] **依赖隔离**：fastjson 老版本只在 extend-alipay 范围内；WxJava 用 Gson 不冲突
- [x] **Token 持久化**：RedisWxCpConfigStorage 多实例安全
- [x] **多应用支持**：corp 下多个 agentId / 多个 appId 各自独立
- [x] **配置外部化**：所有 secret / 私钥走环境变量
- [x] **POC 验证**：链路已通到企微/支付宝服务器

### 6.2 风险清单

| 编号 | 风险 | 严重度 | 缓解 |
|---|---|---|---|
| **R1** | 企微 SDK `setCorpSecret` 在某个未来版本可能改名 | 低 | 单元测试覆盖 + 升级前看 release notes |
| **R2** | 支付宝 `fastjson 1.2.83` 安全扫描会告警 | 中 | 已在白名单中说明；可考虑后续用 Gson 包装层 |
| **R3** | 回调处理 in-process 队列不跨实例 | 中 | M2 阶段切到 Redis Stream / Spring Cloud Stream |
| **R4** | WxCpService 实例每次 `@Qualifier("wxCpServiceMap")` 注入会反序列化 | 低 | 仅启动时构造一次；map 不可变 |
| **R5** | alipay 私钥在 dev 环境用占位符时直接报错 | 低 | 已是预期行为；生产强制环境变量 |
| **R6** | WxJava 内部 Gson 与项目 Jackson 3（tools.jackson.*）可能在 JSON 序列化时冲突 | 低 | WxJava 用 Gson 在自己线程内，与 Spring Web 序列化不交叉 |
| **R7** | 跨时区时间字段（expiresTime）溢出 int | 低 | 已用 `Math.max(60L, ...)` 兜底 |
| **R8** | 业务系统 sys_user 主键 BIGINT 与企微 userid 字符串映射时 type 转换 | 中 | 映射表 `wecom_user_map.user_id` 显式声明 BIGINT |
| **R9** | 企微"通讯录同步"secret 与"自建应用"secret 权限范围不同，混用会报 60011 | 中 | 已在 WeComProperties.contactsSecret 单独配置；文档显式说明 |
| **R10** | Spring Security 6 + SB 4.1 下 `@Anonymous` 注解扫描要求 Controller 必须能被 `RequestMappingHandlerMapping` 找到 | 中 | POC 已验证；后续 Controller 加 `@Anonymous` 时注意放在类或方法上 |

### 6.3 后续必做（按 M1 推进）

2. 写 `/wecom/callback` / `/alipay/notify` 入口
